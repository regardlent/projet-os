2. Architecture (le CLI délègue à la passerelle)

CLI C++ (client de premier niveau, menu + ligne de commande)
  -> invocation "node project-os-bridge.mjs "
      -> SlashCommandRegistry (dist/projects/SlashCommands.js)
          -> handlers /goal /create /addon /autonomy /todo /docs /project
          -> ProjectFactory, ManagedProjectRegistry, AutonomyService...
              -> LocalAI loopback + filesystem

Principe clé : le CLI C++ ne duplique pas la logique — il dispatche une slash-commande réelle à la passerelle Node (qui utilise le registre compilé en dist/) et affiche le résultat. Il lit aussi directement certains JSON de métadonnées (.project-os/project.json, goal.json, todo.json) pour l'affichage de la liste des projets.

6. Protocole passerelle Node (v2)

Le CLI lit une enveloppe v2 produite par bin/project-os-bridge.mjs :

{ "protocol": 2, "requestId": "...", "ok": bool, "status": "...",
  "result": { "command": "...", "ok": bool, "status": "...", "message": "...",
              "next": "...", "warnings": [], "actions": [], "artifacts": [] },
  "timingMs": number, "errors": [] }

La classe CmdResult (pos_runner.hpp) peuple ok/command/status/message/next/warnings/actions/artifacts/raw en lisant result.* (fallback racine pour backward-compat).

ChampTypeSens
protocolint (2)Version du protocole.
requestIdstringCorrélation (env PROJECT_OS_REQUEST_ID ou auto req-...).
ok / statusbool / stringStatut global (READY, NAV, UNKNOWN_COMMAND, BLOCKED...).
result.messagestringMessage utilisé par le CLI pour l'affichage.
result.artifactsstring[]Artefacts produits (ex. .project-os/project.json).
timingMsnumberLatence mesurée du dispatch.

9. État du CLI & limites (honnêteté)

  • Fonctionnalités livrées : menu interactif 9 entrées, mode non-interactif scriptable, navigation doc officielle (/docs), état projet (/project), goal/todo/addon/autonomy/create dispatchés à la passerelle, gestion d'erreur structurée.
  • Rôle : client de premier niveau — délègue la logique métier à la passerelle Node (registre slash en dist/) ; ne duplique PAS la logique.
  • Protocole v2 : enveloppe versionnée (protocol/requestId/timingMs/exitCode) lue par CmdResult.
  • Limites : mode non-interactif qui retourne toujours exit 0 (à durcir avec un exit code ≠ 0 en échec) ; pas encore de commandes status/report/models/gpu dédiées dans le menu ; shellQuote minimaliste (pas toutes les règles de quoting Windows) ; pas de timeout explicite sur _popen.
