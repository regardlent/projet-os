🛠️ Project OS — Guide complet d'utilisation

v0.1.0 Pilotage de projets par commandes, moteur IA local (LocalAI). Ce guide se passe de l'IDE Cline : on utilise les commandes slash et les fichiers directement.

Prérequis GPU (obligatoire pour la ladder). Project OS exige un vrai GPU. Pas de fallback CPU pour la validation d'endurance. Vérifier : nvidia-smi --query-gpu=memory.free → il faut > ≈3,0 Go libres pour un modèle Q4 2–3 Go. Seul l'utilisateur peut fermer les applications GPU externes (jamais de kill automatique de process).

2. Commandes slash (contrôle des projets)

Elles s'utilisent dans la console d'input de Project OS (extension VS Code/Antigravity), préfixées par /. Types de projets pilotés : cpp, ts, web, node.

CommandeDescriptionExemple
/createCrée un projet neuf (scaffold)./create myproject type=cpp
/goalDéfinit l'objectif (critères mesurables)./goal "Observe Swiss ligue" showStandings showScorers
/todoListe (barré) / ajoute / marque une tâche./todo list, /todo done impl
/addonGère les addons (core, cpp, web, node)./addon add project-os-cpp
/autonomyLance un run autonome (analyse/enrichissement)./autonomy plan --minutes=60, /autonomy run
/docsNavigation des sources officielles en ligne./docs ligue
/projectRésumé d'un projet géré./project projet-gere
/reportRapport tokens/cost/perf d'un job./report --job=run-60min

3. Créer & piloter un projet (exemple réel)

cd C:\Users\eiden\Desktop\dev\projects
/create projet-gere type=cpp
/goal "Observe Swiss ligue" showStandings showScorers
/todo add "Implement standings/scorers"
/todo done scaffold
/autonomy plan --minutes=60

/report --job=run-60min          # tokens + coût + perf

8. Règles de sécurité non négociables

  • Jamais de kill de process ni de reset Docker/Windows ; l'utilisateur contrôle les apps GPU externes.
  • Jamais de CPU fallback, de PASS simulé, ni de qualification inventée.
  • Licence ≤ Apache/4B, SHA vérifiée, Defender "NO KNOWN MALWARE INDICATORS".
  • Flag trust_remote_code=false obligatoire (BLOCKED si requis).
